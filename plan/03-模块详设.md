## 1. 模块① 编目构建（`build`）

### 1.1 编目源格式（`data/catalog/<platform>.yaml`）

每条形如：

```yaml
- name: EADDRINUSE
  domain: errno
  value: 98
  source:
    file: include/uapi/asm-generic/errno.h
    line: 191
    repo: torvalds/linux
    ref: <记录抽取时的 commit sha>
  description_zh: "地址已被占用"
  posix_ref: "POSIX.1-2017 XSH <errno.h>: EADDRINUSE"
```

### 1.2 字段契约

| 字段 | 必填 | 判据 |
|---|---|---|
| `name` | ✅ | 大写标识符；同平台同域内唯一 |
| `domain` | ✅ | ∈ `DOMAINS`（`contract.py`）——**四域**：`errno` / `signal` / `exit` / `node` |
| `value` | **按域** | 有值域（`errno`/`signal`/`exit`）：非布尔整数；**无值域（`node`）：必须缺省** |
| `source.file` | ✅ | 相对仓库路径，不以 `/` 开头 |
| `source.line` | ✅ | 正整数。**无行号者不得入编目**，记入 `data/gaps.md` |
| `source.repo` + `source.ref` | 运行时视角另算 | 本机实读项（Windows 双视角）用 `source.kind: runtime` + `runtime` + `program_version`，见 1.3 |
| `description_zh` | ✅ | 一句话，来源必须是原文注释或官方文档；不得自行解释成因 |
| `posix_ref` | 可空 | 空则写哨兵 `"<none>"`（**不写空串**——空串与"没填"不可区分） |

> **M2 起 `value` 由域决定，不是"一律必填整数"**（K23）：`ERR_*` 只有字符串码名，
> 没有数字码值。给它编一个数字是编造，写 `value: null` 又会与"查不到值"混成一件事 ——
> 所以无值域的条目**根本不写这个字段**。装载期两侧（生成侧与装载侧）各自 fail-closed 校验。

### 1.3 运行时视角条目（Windows 双视角）

Windows 两条编目来自本机实读，没有头文件行号，改用三态化的出处块：

```yaml
- name: EADDRINUSE
  domain: errno
  value: 100
  source:
    kind: runtime           # file | runtime
    runtime: node           # node | python
    program_version: v24.15.0
    verified_at: 2026-11-01
  posix_ref: "<none>"
```

> **硬纪律**：`kind: runtime` 的条目**不得**冒充头文件条目。`build_catalog.py` 装载期 fail-closed：
> `kind` 缺省、`file` 与 `runtime` 同时出现、`line` 缺失而 `kind: file` —— 任一情况直接 `CatalogError`。

### 1.3b 文档锚点条目（`kind: doc`，M2 首次实战）

`sysexits` 与 Node 错误码来自官方文档页，**指不到行号**（网页排版一变行号全错）。改用段锚：

```yaml
- name: EX_USAGE
  domain: exit
  value: 64
  source:
    kind: doc
    url: https://man.openbsd.org/sysexits
    anchor: "#EX_USAGE"     # 页内锚，不是文件名
    verified_at: 2026-11-01
  posix_ref: "<none>"
```

| 判据 | 硬性要求 |
|---|---|
| `source.url` | 必须 `https://` —— 装载期就挡，不留到报告期 |
| `source.anchor` | 非空且是页内锚（`#EX_USAGE` / `#err_ambiguous_argument`） |
| 强度 | **恒为 `diff`**（`contract.SOURCE_MAX_STRENGTH["doc"]` 写死）；**拿不到 `hard`** |
| 报告形态 | `source_label` = `doc:#<anchor>`（零外链：人读表不输出 URL，`plan/03` §4.1 第二律） |

> **为什么不能只留一份**（《`sysexits` 的名字 vs 编目》）：
> 判定**不许依赖编目**（K22：`exitcode 64` 在空编目上也必须判 `SYSEXITS`），所以代码内
> `SYSEXITS_NAMES` 必须在；而报告要带出处锚，所以编目也必须在。
> **两份就必然有漂移风险** —— `tests/test_catalog_m2.py::test_code_table_and_catalog_are_two_copies_that_agree`
> 就是那个风险的门（双向一致，不是单向包含）。
>
> 说明：`plan/04` §2.3 早期把它写成 `url_anchor`，实现时拆成 `url` + `anchor` 两个字段 ——
> 一个字段塞两件事（站点 + 段锚）就没法在装载期分别校验。本表是现行口径。

### 1.4 生成器与冻结

`tools/build_catalog.py`：

| 子命令 | 行为 |
|---|---|
| `--out <path>` | 读 `data/catalog/*.yaml` → 写 `<path>/catalog.json` + `catalog.manifest.json` |
| `--check` | 内存重算，与仓库内的冻结件**逐字节**比对；不一致 → exit 1 并逐条打印差异键 |

manifest 只含**结构事实**，不含会漂的数字：

```json
{ "schema_version": 1, "generator_version": "0.1.0",
  "entry_count": {"errno": 0, "signal": 0},
  "sha256": "<行尾归一后的 catalog.json 摘要>",
  "platforms": ["linux","macos","win32-node","win32-python"] }
```

> `entry_count` 是**由构造算出**的（逐条累加），不是手写常量——新增一个平台文件分母自动变。

### 1.5 判定顺序（写死，不许"先到先得"）

```
装载 → 逐文件校验 kind → 域校验 → (platform, domain) 重复 name → 重复 (platform, domain, value) 记账
```

`(platform, domain, value)` 出现多个 name 是**合法的**（`AMBIGUOUS-SAME-PLATFORM` 的素材），
`(platform, domain, name)` 出现两个 different value 才是**硬错**（`CatalogError`）。

## 2. 模块② 数字→语义判定（`explain`）—— 招牌模块

### 2.1 入口

```
errcode-atlas explain <number|name> [--platform linux|macos|win32-node|win32-python]
                      [--platform win32  → exit 4 + 提示两个视角]
                      [--domain errno|signal|exit] [--json]
```

- `<number>` 与 `<name>` **自动判别**：全数字（可带负号）→ 数字查询；否则按常量名查询。
- `--platform` 缺省 → 跨平台模式（可能产出 `AMBIGUOUS-CROSS-PLATFORM`）。
- `--domain` 缺省：数字形态先查 `errno`、再查 `signal`；两域都有命中且不同 → `AMBIGUOUS-CROSS-PLATFORM`（跨域同值）。

### 2.2 判定顺序（写死并测，不许重排）

| 序 | 输入形态 | 条件 | 结果 |
|---:|---|---|---|
| 1 | 数字 + 平台 | 该 `(platform, domain, value)` 命中 1 个 name | `UNAMBIGUOUS` |
| 2 | 数字 + 平台 | 命中 ≥2 个 name | `AMBIGUOUS-SAME-PLATFORM`（**列出全部候选 + 区分方式**） |
| 3 | 数字 + 无平台 | 各平台命中集合不一致，**或**该域已覆盖的某个平台上没有这个值 | `AMBIGUOUS-CROSS-PLATFORM`（**逐平台列值**） |
| 4 | 数字 + 无平台 | 该域**已覆盖**的平台上 name 集合一致且都存在 | `UNAMBIGUOUS`，`platforms_agree: true` |
| 5 | 名字 + 平台 | 该平台无此 name，但**别的平台有** | `PLATFORM-ABSENT`（列出"哪些平台有，值各是多少"） |
| 6 | 名字 + 平台 | 该平台有此 name | `UNAMBIGUOUS` |
| 7 | 名字 + 无平台 | 该 name 在**全部已覆盖平台**上都有定义（**取值可以不同**） | `UNAMBIGUOUS`，逐平台列值；`notes` 写"跨平台取值差异不构成歧义" |
| 8 | 名字 + 无平台 | 该 name 在某个已覆盖平台上**没有定义** | `PLATFORM-ABSENT`（`platform_absent_in` 列出缺的**全部**平台） |
| 9 | 任一形态 | 编目内完全无此值/名 | `UNKNOWN`（exit 3） |

> **序 7 是 M2 补上的那一行（`plan/06` G6）**：M1 装载真实编目后实测
> `explain EAGAIN`（未给平台）返回 `UNAMBIGUOUS` / exit 0 并列 11/35/11/11，
> 而原表七行没有覆盖这个形态 —— 文档与代码各说一套。
>
> **定稿口径 = 序 7 现在的写法，理由是"名字查询确有唯一答案"**：问 `EAGAIN`
> 问的是"这个名字有没有定义"，四个平台都有，答案唯一；**取值不同是事实，不是歧义**
> （歧义的定义是"一个问题有两个答案"，不是"同一个名字在不同平台数值不同"）。
> 所以 `data/README.md` §5.2 那句把 `EAGAIN → 11/35/11` 举作
> `AMBIGUOUS-CROSS-PLATFORM` 样本的话**已改口**（跨平台歧义的样本必须是**数字**查询）；
> 两边不许各留一套 —— 这是 M1 实测踩到的"文档说 A、代码做 B"。
>
> 序 7 与序 8 的分界正是本题的一等公民：**"各平台都有、值不同"**（唯一答案）
> 与 **"某个平台根本没有"**（`PLATFORM-ABSENT`）不是一件事。

> **序 8 的分母也是"该域已覆盖的平台"**（M3 修）：原先实现拿 `catalog.platforms()`
> （= 全编目里出现过的平台）当分母，于是 `explain ERR_AMBIGUOUS_ARGUMENT`（不给平台）
> **每次都**判 `PLATFORM-ABSENT` —— `node` 域不挂 `win32-python`，而 `win32-python`
> 因为在别的域有条目，于是"在编目里出现过"。那正是 `data/README.md` §2.3 警告的
> **假 `PLATFORM-ABSENT`**：`win32-python` 上根本没有这套码，它的缺席是"这套码在那里
> 不成立"，不是"那里缺了一条"。M3 由
> `tests/test_judgement_order.py::test_row_3_uncovered_platform_is_not_counted_as_divergence`
> 抓到（该测试先红，再改实现）。判据与序 3 同一条 —— 序 3 与序 8 必须用同一个分母，
> 否则同一个域在两个形态上给出互相矛盾的"缺了谁"。

> **序 3/4 的分母是"该域已覆盖的平台"，不是"全部四个平台"**（`catalog.covered_platforms`）。
> 未覆盖的平台是**"还没查"**，不是"查过没有"：
> 把它算进分歧 → 编目半途时每条都判 `AMBIGUOUS-CROSS-PLATFORM`（假歧义）；
> 把它完全忽略 → "只有 linux 有"会被判成"各平台一致"（假唯一）。
> 判据 = **"这个平台的缺席，是'我查过没有'，还是'我还没查'？"**——只有前者算分歧。
> 未覆盖的平台会写进 `notes`（可见，但不进判定）。
>
> **序 3 的"缺席平台"必须进结构字段 `platform_absent_in`**（M3 定稿，实现跟进）：
> 序 3 的触发条件之一是"该域已覆盖的某个平台上没有这个值"，那件事实原先只写在
> `distinguish` 散文里 —— 消费方得自己反推 `covered_platforms` 才知道少了谁，
> **人读得到、机读不到**。M3 的种子语料在 `11 --domain errno`/`19 --domain signal`
> 等 6 条 case 上把这件事实写成真值，`bench` 当场把差异报出来（`platform_absent_in`
> 期望非空、实得空），于是判定层补上了这一字段。**分母纪律不变**：仍未覆盖的平台
> 既不进 `per_platform` 也不进本字段。断言在
> `tests/test_judgement_order.py::test_row_3_absent_platform_on_covered_domain_is_reported`。

> 第 5 与第 7 的区别是本题的一等公民：**"这个平台没有" 与 "我不知道" 不是一件事。**
> 前者能给出"另两个平台的取值"，后者只能说"编目未覆盖"。

### 2.3 输出结构（`--json` 的 schema）

```json
{ "verdict": "AMBIGUOUS-SAME-PLATFORM",
  "query": {"kind": "number", "value": 6, "platform": "linux", "domain": "signal"},
  "candidates": [{"name": "SIGABRT", "value": 6, "source": {...}}, {"name": "SIGIOT", ...}],
  "distinguish": "同值别名：SIGIOT 是 SIGABRT 的历史别名，二者不可区分；需按上游声明区分",
  "platform_absent_in": [],
  "notes": ["128+n 是 POSIX 惯例而非标准"],
  "sources": ["<file>:<line>", "..."] }
```

**每条判定必须带 `sources`**（`plan/01` §六 结论纪律）。

### 2.4 纪律

- `AMBIGUOUS-*` 退出码 1，**不是失败**；人读表头写"判定完成：不可唯一归因"。
- 候选排序 = `(value, name)` 字典序，**不按"可信度"排**（排序里不许藏倾向）。
- 不允许自动收敛：绝不因为"最常见的那一个"就只报一个。

## 3. 模块③ 退出码归因（`exitcode`）

### 3.1 入口

```
errcode-atlas exitcode <code> --platform <platform> [--json]
```

### 3.2 判定顺序（写死并测）

| 序 | 条件 | 结果 |
|---:|---|---|
| 1 | `code < 0` 或 `code > 255` | 越界 → `UNATTRIBUTABLE`（附中文说明；Windows 巨型码见 3.4） |
| 2 | `64 ≤ code ≤ 78` | `SYSEXITS(n)`，**标注"约定非标准"**，并给出该码的 `sysexits` 名 |
| 3 | `code == 0` | `NORMAL-EXIT` |
| 4 | `128 < code ≤ 128 + max_signal(platform)` 且 `code - 128` 在该平台是**有效信号** | `SIGNAL-KILLED(n)` + 信号名 |
| 5 | `1 ≤ code ≤ 127` 且不属于 64–78 | `NORMAL-EXIT`，其中 `code == 1` **必须**在 `notes` 写"通用失败，无特定语义" |
| 6 | 其余 | `UNATTRIBUTABLE` |

> 顺序 2 排在 3/4 之前是刻意的：**约定段优先于惯例段**，且 `64–78` 与 `128+n` 不重叠，
> 但若未来扩展信号表导致重叠，这个顺序必须仍可解释（测试里锁死）。

### 3.3 硬判据（`plan/01` §二 模块③）

- `exit 1` → `UNATTRIBUTABLE`，`notes` 明写"通用失败，无特定语义"。
- `128+n` 必须**同时**验 `n ∈ 该平台有效信号编号集合`；`n=0` 与 `n` 不在集合内 → `UNATTRIBUTABLE`。
- **可演示的错判陷阱**：`SIGSTOP` 在 Linux 是 19、在 macOS 是 17（`data/README.md` §1.2，已核对原文）。
  于是 `147` 在两个平台上归到的**不是同一个信号**——编目装载后由 `macos.yaml` 的 19 号条目决定具体名字，
  **不得在代码里写死信号名**。这条同时是 `bench` 的必测样本（跨平台归因分叉）。

### 3.4 Windows 巨型退出码

`18446744072635809792` 一类（`0xFFFFFFFFxxxxxxxx`）是 32 位无符号截断的产物。
归因规则：若 `code` 落在 `[2**32, 2**64)` 则先按 `code & 0xFFFFFFFF` 解释，并在 `notes` 里
**显式声明"已按 32 位截断解释，原值不可唯一归因"**，`verdict` 仍取归因结果但 `truncated: true`。

## 4. 模块④ 报告与退出码

### 4.1 渲染三律

1. **零判定**：`report.py` 只做"结果对象 → 字符串"，不含任何 `if verdict == ...` 分派（AST 断言守门）。
2. **零外链**：人读表不输出 URL；出处一律 `<相对路径>:<行号>` 形态（`source.kind == runtime` 输出 `runtime:<程序> <版本>`）。
3. **确定性**：同一结果对象两次渲染逐字节相等（`selftest` 断言）。

### 4.2 退出码映射（唯一处：`cli.py::_exit_code_for`）

| 结果 | 退出码 |
|---|---:|
| `UNAMBIGUOUS` / `SIGNAL-KILLED` / `NORMAL-EXIT` / `SYSEXITS` | `0` |
| `AMBIGUOUS-*` / `UNATTRIBUTABLE` / `PLATFORM-ABSENT` | `1` |
| `UNKNOWN` / 编目缺失 / 域不支持 | `3` |
| 用法错误（未知子命令、缺参数、`--platform win32`） | `4` |

> `argparse` 原生是 `SystemExit(2)`；入口统一捕获并映射成 `4`（`plan/02` D5）。
> 测试要同时断言 `cli.main([...]) == 4` 与 `subprocess` 的真实退出码——两条形态不许漂。

## 5. Agent Skill 契约块（M5 落地，此处先定字段）

`SKILL.md` 里的契约块声明四件事，`tests/test_contract.py` 做**双向**断言：

| 方向 | 断言 |
|---|---|
| 文档 → 代码 | `SKILL.md` 契约块里出现五个 `verdict` 值、四个 `attribution` 值、四个平台值、`0/1/3/4` 退出码，**逐一 ∈ `contract.py` 的常量集合**，且**数量相等**（集合相等而非包含） |
| 代码 → 文档 | `contract.py` 的每个常量值在 `SKILL.md` 契约块里出现 |

> 单向包含会漏"文档多写了一个已废弃值"；只有集合相等才同时管住两个方向。
> 契约块用固定围栏标记 `<!-- contract:begin -->` / `<!-- contract:end -->` 界定扫描面，
> 避免把 SKILL.md 正文里的示例词误当契约。

## 6. 自测与基准

| 命令 | 内容 | 出口 |
|---|---|---|
| `errcode-atlas selftest` | 内置不变量：双跑确定性、退出码映射、`exit 1` 判定、五态可达性 | 全过 → 0 |
| `errcode-atlas bench` | 跑 `fixtures/*/expected.json`，逐 case 比对 `verdict` / `attribution` / 退出码 | 全过 → 0；有差异 → 1 并逐条打印 |
| `pytest -q` | 单元 + 契约 + 门自检 + 变异 harness | 全过 → 0 |

`bench` 的判据必须是**结果对象**而非渲染文本（`plan/02` D4）。
