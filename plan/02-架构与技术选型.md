## 1. 分层

一句话：**编目是数据，判定是纯函数，呈现是壳。** 三层之间单向依赖，任何一层都不许回头看上一层。

```
┌─────────────────────────────────────────────────────────────┐
│ 呈现层  cli.py（argparse） · report.py（人读表 / --json）      │  只做 argv→调用→退出码
├─────────────────────────────────────────────────────────────┤
│ 判定层  explain.py（数字/名字→判定态） · exitcode.py（码→归因）│  纯函数，无 I/O、不读时钟
├─────────────────────────────────────────────────────────────┤
│ 编目层  catalog.py（装载冻结 JSON + 建索引）                   │  只读随包数据
└─────────────────────────────────────────────────────────────┘
        ▲                                    ▲
        │ 生成（dev 侧，一次性）              │ 校验（运行期，零依赖）
  tools/build_catalog.py ──► src/errcode_atlas/data/catalog.json
        ▲                                    │
  data/catalog/*.yaml（唯一编目真相源）        └──► errcode-atlas build --check
```

### 1.1 三条分层纪律

| # | 纪律 | 为什么（踩过的那条） |
|---|---|---|
| L1 | **判定层不 import 呈现层** | 否则"加一个 `--json` 字段"就会顺手改判定语义，基准与 CLI 各说一套。 |
| L2 | **判定层不读时钟、不读环境变量、不联网** | 双跑逐字节一致的前提。`selftest` 断言"同一输入两次调用结果字节相同"。 |
| L3 | **编目层的唯一入口是 `catalog.load()`** | 别处不许自己 `json.load`。索引在装载期一次建好，判定层只做集合查询。 |

### 1.2 生成侧与生产侧各一份实现（刻意不共享）

`tools/build_catalog.py`（dev 侧，PyYAML）把 YAML 编译成 JSON；`catalog.py`（生产侧，零依赖）只读 JSON 并自建索引。
**两侧都不做语义判定**，只做形状与索引——判定只在判定层发生。

> 共享一份"索引构造"会让"生成器 `--check` 绿" 与 "运行期能查到" 变成同一件事的两个说法，
> 一旦生成器写错索引，两侧一起错、`--check` 照样绿。刻意不共享，一致性靠 `tests/test_catalog_build.py` 的逐字节与逐条对账。

### 1.3 模块 ↔ 目录

| 题目模块 | 实现位置 | 备注 |
|---|---|---|
| ① 编目构建 `build` | `tools/build_catalog.py`（生成，dev）+ `errcode_atlas.cli` 的 `build --check`（校验，运行期） | 见 §3 决策 D2 |
| ② 数字→语义判定 `explain` | `errcode_atlas/explain.py` | 招牌模块 |
| ③ 退出码归因 `exitcode` | `errcode_atlas/exitcode.py` | `128+n` 必须验 `n` 有效 |
| ④ 报告与退出码 `report` | `errcode_atlas/report.py` + `cli.py` 的退出码映射 | 人读表 / `--json` 双轨 |

## 2. 契约（代码侧唯一常量表）

`src/errcode_atlas/contract.py` 是**代码侧的唯一定义处**，四张表：

| 常量 | 内容 | 唯一口径来源 |
|---|---|---|
| `PLATFORMS` | `linux` / `macos` / `win32-node` / `win32-python` | `data/README.md` §1.1（Windows 双视角） |
| `DOMAINS` | `errno` / `signal` / `exit` | `plan/01` §二 |
| `VERDICTS` | 五判定态 | `data/README.md` §5.2 |
| `ATTRIBUTIONS` | 四归因 | `data/README.md` §5.3 |
| `EXIT_CODES` | `0/1/3/4` | `data/README.md` §5.1 |

**双向断言**：`tests/test_contract.py` 把 `data/README.md` §5 的两张表**反向解析**成集合，与 `contract.py` 逐项比对——
文档→代码、代码→文档各一遍。任一侧多一个值或少一个值即红（`AMBIGUOUS` 少一个子态正是本题最贵的错）。

> 为什么不是"人抄一遍文档进代码"：§5 是唯一真相源，代码是它的**解析结果**，不是它的复述。
> 解析器必须显式 `continue` 表格分隔行，并断言"解析出的行数 > 0"——否则表被切碎时"空 == 空"恒绿。

`SKILL.md`（M5）里的契约块与 `contract.py` 再做一对同构断言，见 `plan/03` §5。

## 3. 技术选型与决策

| # | 选型 | 结论 | 理由 / 备选被否原因 |
|---|---|---|---|
| **D1** | 语言 | **Python ≥ 3.10**，纯标准库 | 判定是集合查询与整数比较，无需生态；PyYAML 只在 dev 侧出现（见 D2）。Go 会多一轮"工具链不在 PATH"的环境成本，Node 则把"零依赖"变成要论证的东西。 |
| **D2** | 编目载体 | **YAML 源（`data/catalog/*.yaml`，带行号）→ 冻结 JSON（随包）** | 题目要求编目源是"结构化 YAML 含出处行号"；运行期零依赖则不能带 YAML 解析器。生成=dev 侧（PyYAML，`[dev]` extra），装载=运行期（只读 JSON）。**`errcode-atlas build` 因此是校验面 + 冻结面，不是解析面**——偏差登记见 `plan/06` G1。 |
| **D3** | Windows 平台粒度 | **`win32-node` / `win32-python` 两个平台值；`--platform win32` 判用法错误（exit 4）并提示两个视角** | 同机实测 Node `100` / Python `10048`（`data/README.md` §1.1）。写一个 `windows` 值是**已知错误**。加第六个判定态（`AMBIGUOUS-CROSS-VIEW`）会破坏"五态封闭"（`plan/00` §2.1 决策），故把差异**下沉到平台轴**。 |
| **D4** | 判定类型 | 判定层**纯函数 + dataclass**，返回结构化结果，不做任何格式化 | 报告与基准吃同一份结果对象；否则 `bench` 验的是渲染不是判定。 |
| **D5** | 退出码映射 | **只在 `cli.py` 一处做 `结果 → 退出码`** | 判定层不返回退出码——否则同一个判定在两个入口给出两个码（`data/README.md` §5.1 的硬纪律会被绕过）。 |
| **D6** | 错误输出 | 全部走 stderr，单行 + 可机读前缀 `errcode-atlas: `；`--json` 时错误也出 JSON 到 stderr | 让 CI 能 `2>` 分离。 |
| **D7** | 数据摘要口径 | 编目 JSON 的 sha256 **按行尾归一后**计算（`\r\n`→`\n`），配 `.gitattributes` `* text=auto eol=lf` | 否则 `git archive` 导出树（受 `core.autocrlf`）算出的摘要与仓库值不同，装好的包直接 exit 3。 |
| **D8** | 测试 | `pytest`，`tests/` 无 `__init__.py` | 与 `py -3.12` / `py -3.8` 双通道兼容；见 `plan/05` 的"已知未验证项"。 |

## 4. 构建

### 4.1 布局

`src` 布局 + `pyproject.toml`（setuptools）：

```
src/errcode_atlas/
  __init__.py        # __version__ 唯一定义处之一（另一处 = pyproject）
  __main__.py        # python -m errcode_atlas
  cli.py             # argparse + 退出码映射（唯一处）
  contract.py        # 五态/四归因/四平台/三域/退出码
  catalog.py         # 装载 + 索引
  explain.py         # 模块②
  exitcode.py        # 模块③
  report.py          # 模块④ 渲染
  data/catalog.json  # 冻结编目（随包）
  data/catalog.manifest.json  # 摘要 + 条目数 + 生成器版本
```

### 4.2 版本号两处一致

`pyproject.toml [project].version` 与 `src/errcode_atlas/__init__.py:__version__` 必须相等，
由 `tests/test_version_floor.py` 的一条断言同时校验（外加 README 顶部标同名版本）。

### 4.3 构建命令

```bash
py -3.12 -m venv .venv
./.venv/Scripts/python.exe -m pip install -e ".[dev]"      # Git Bash 下的相对形式
./.venv/Scripts/python.exe tools/build_catalog.py --check  # 生成器冻结态校验
./.venv/Scripts/python.exe tools/check_sprint_layout.py    # 布局门
./.venv/Scripts/python.exe tools/check_desensitized.py     # 脱敏门
./.venv/Scripts/python.exe -m pytest -q
```

CI 侧另见 `.github/workflows/ci.yml`；离线镜像见 `.github/offline.Dockerfile`。
**构建期不得不联网（拉镜像 / 装 dev extra），运行期零网络**——`--network none` 那条 job 证明的是后者。
